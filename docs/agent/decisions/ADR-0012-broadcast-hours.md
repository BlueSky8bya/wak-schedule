# ADR-0012: 방송 시간 추적 재도입 — 고정 부하(라이브 캐시 피기백) 방식

Status: Accepted
Date: 2026-08-26
Decision Owners: User (요구) + Agent (방식 설계)
Related: ADR-0004(유지 — 요청당 쓰기 금지 원칙은 그대로), ADR-0011(지표 범위 갱신)

## Context

'이 달 기록'·인사이트 트렌드의 방송 시간 카드를 사용자가 요구했다. VIC의 방송시간
추적은 크론+VOD 보정 체계였고 fork 때 통째로 제거됐다(ADR-0004의 수집 계열).

## Decision

쓰기 부하가 시청자 수와 무관하게 고정되는 방식으로만 재도입한다:

- 원천: /api/live의 **서버 20초 캐시 갱신 순간**에만 세션 도장(분당 최대 3회 쓰기).
  시청자 폴링 수와 무관 — ADR-0004의 "요청당 쓰기 금지"를 지킨다.
- 시작시각 = SOOP BTIME 기반 startedAt(세션 키) — 폴링이 늦어도 정확.
- 종료 = 오프라인을 본 순간 last_seen_at으로 닫음(폴링 공백을 방송시간으로 안 부풀림).
- 저장: broadcast_sessions(0064) — 공개 읽기 허용(방송 시간은 공개 정보),
  집계는 public-loader가 KST 일 단위 겹침 분할로 계산, /api/public/<slug>/broadcast로 서빙.
- 한계: 시청자가 아무도 안 여는 시간대(무관중 새벽)는 캐시 갱신이 없어 표본이 성길 수
  있다 — 시작시각은 BTIME이 보정하고, 종료는 마지막 목격 시각 기준(보수적).
  VIC의 VOD 보정·외부 크론은 도입하지 않는다(필요해지면 Revisit).

## Consequences

- (+) '이 달 기록'·트렌드에 방송 시간 카드(VIC BroadcastHours 그대로).
- (−) 배포 후부터 쌓인다 — 과거 방송은 소급 불가.

## Revisit Conditions

표본 공백이 실제로 문제가 되면(무관중 시간대) 외부 크론 1분 폴링 추가 검토.
