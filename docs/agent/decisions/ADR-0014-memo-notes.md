# ADR-0014: 메모 개편 — 월별 단일 메모 → 붙임쪽지 런처 + 떠 있는 쪽지 창

Status: Accepted (ADR-0009 대체)
Date: 2026-08-26
Decision Owners: User (요구 — 참고 스크린샷 3장) + Agent (설계)

## Context

레일의 '이 달 메모'(월별 단일 텍스트영역, ADR-0009)를 사용자가 개편 요구:
`+`로 메모를 여러 장 만들고, 행을 누르면 떠 있는 쪽지 창이 열리며, 창은 마우스로
움직이고 글자 크기·글씨체 등을 설정할 수 있어야 한다.

## Decision

- 데이터: 새 테이블 `calendar_memos`(0065) — (calendar, user) 스코프, 쪽지 여러 장.
  **월(ym) 구속 제거** — "매 달 방향성"처럼 달을 넘는 메모가 자연스러움.
  RLS `is_calendar_admin AND user_id = auth.uid()`(0063 문법) + service_role GRANT.
- 기존 `calendar_month_memos`는 보존(파괴 없음), 내용은 1회 이식(제목 "N월 메모").
- 서식은 **쪽지 단위**: 배경색 4(노랑·민트·하늘·분홍) / 굵게 / 글씨체 3(고딕·명조·모노) /
  크기 4(13·15·18·22). 본문은 plain text — contentEditable 리치텍스트(부분 서식)는
  받지 않는다(XSS 표면·복잡도 대비 요구 초과).
- 창 위치는 localStorage(기기 편의), 서버엔 내용·서식만. 창은 body 포털(fixed) —
  scene transform에 안 깨지게. 한 번에 한 장. 창 모서리 resize 허용.
- 저장: 디바운스 1.2s + blur 즉시 + 직렬 큐(월별 메모의 검증된 문법 승계).
  서버 액션은 memo-actions.ts에 동거(관리자 전용 데이터 — BR-CACHE-001 EXCEPT 승계).
- 한도: 계정당 30장, 본문 4000자, 제목 100자.

## Consequences

- (+) 메모 여러 주제 병행, 달 넘는 메모, 쪽지 갬성(색·서식).
- (−) 모바일 편집실엔 레일이 없어 진입점 없음(월별 메모 때와 동일) — 필요 시 별건.
- 참고 이미지의 체크리스트형(To do, 남은/완료 카운트)은 이번 범위 밖 — 요구가
  생기면 본문 문법(`- [ ]`) 또는 타입 컬럼으로 별도 설계.

Revisit: 체크리스트형 메모 요구 시. 실계정 다수 사용 시 한도(30장) 재검토.
