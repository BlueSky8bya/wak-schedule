# ADR-0015: 메모 P0 — 수동 순서·저장 신뢰 + 사용자 심판 4건 (ADR-0014 후속)

Status: Accepted
Date: 2026-08-26
Decision Owners: User (심판) + Codex 감사 문서(docs/ux/memo-notes-apple-hci-redesign-plan.md) + Agent (구현)

## Context

Codex의 메모 Apple HCI 감사가 P0 두 개(수정하면 탭이 점프하는 updated_at 정렬,
저장 실패 유실)와 구조 결함들을 확정했다. 문서의 "고정된 사용자 결정" 일부가
기존 지시와 상충해 사용자가 직접 심판했다.

## 사용자 심판 (2026-08-26)

1. `+` 버튼: 헤더 **오른쪽 끝** (제목 옆 배치를 뒤집음)
2. 색상: **메뉴 없이 상시 노출 스트립** (⋯ 메뉴 안 배치를 뒤집음)
3. 글씨체: **분위기 4~5개로 축소** (11종 노출을 뒤집음 — 깔끔·책처럼·메모펜·둥글게·모노)
4. 크기: **−/+ 스테퍼로 4단계 이동** (작게14·기본16·크게18·아주 크게22)

기존 저장값 호환: 옛 글씨체 키는 계속 렌더('기존 글꼴' 표시), 옛 임의 크기는
가장 가까운 단으로 표시하고 사용자가 바꿀 때만 새 값 저장.

## Decision

- **수동 순서가 진실**: calendar_memos.sort_order(0066, backfill = 기존 최신순),
  목록은 sort_order asc. 본문 수정은 updated_at만 바꾼다(점프 없음).
  재정렬은 reorder_calendar_memos RPC(단일 UPDATE = 원자, invoker RLS) +
  서버 검증(본인 전체 집합 일치·중복 거부). 새 메모 = 맨 위(min-1, 음수 허용).
- **저장 코디네이터가 부모 소유**: 메모별 pending/inflight 큐, 실패 patch는
  pending에 남아 '재시도'로 살아남는다. 창을 닫아도 저장 계속. beforeunload 경고.
  update는 서버 updatedAt을 반환해 로컬 갱신.
- **탭 드래그 재정렬**: lib/tags/reorder(edge·데드존·같은참조 no-op) 재사용,
  유령 1:1, Esc/실패 시 서버 확정 순서로 복구 + 재시도 배너.
- 구조 수정: 탭 = 손잡이/열기/삭제 **형제 버튼**(중첩 제거), 같은 탭 재클릭 =
  닫기가 아니라 본문 초점, 위치 저장은 posRef(최신값), clamp에 높이 반영.
- 6색: paper·lavender 추가(감사 문서 11-2 팔레트), 파스텔은 메모지·스트립에만.
- 탭 둘째 줄 = 내용 미리보기(글자 수 표시 제거).

## 범위 밖(후속 후보)

모바일 시트(ADR-0014 범위 변경 — 별도 결정), 검색, soft delete+Undo, 복제,
기본 메모 모양, 키보드/메뉴 재정렬 대안(문서 §9-5 — 다음 라운드).
chrome 색은 Sky가 아니라 현행 보라/골드 문법(ADR-0013 유지).
